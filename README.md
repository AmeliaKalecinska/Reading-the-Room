# Repository Overview

This repository contains all materials for the dissertation study evaluating **autonomy-taking behaviour** in large language models across implicit trust conditions. The study uses the [Bloom](https://meridianlabs-ai.github.io/petri_bloom/) evaluation framework. automated behavioural evaluation pipeline to generate, run, and judge conversational scenarios.

---

## Design at a Glance

| Parameter | Value |
|---|---|
| Target models | Claude Opus 4.7, GPT-5.5 |
| Scenarios | 50 (base) × 3 conditions = 150 variations |
| Repetitions per variation | 6 |
| Total transcripts | 1,800 (900 per model) |
| Auditor model (rollout) | Claude Opus 4.7 |
| Judge model | Claude Opus 4.7 |
| Trust conditions | Base · High Implicit Trust · Low Implicit Trust |

### To understand the experimental design
- **`autonomy/BEHAVIOR.md`** — defines autonomy-taking and its five axes
- **`autonomy/scenarios/understanding.md`** — the pipeline's structured analysis of the behaviour, including what the two trust conditions manipulate and validity constraints
- **`bloom-data/seed.yaml`** — full pipeline configuration (models used, repetitions, temperature, judgment qualities)

### To inspect the scenarios
- **`bloom-results/autonomy/ideation.json`** — all 150 scenario variations (50 base × 3 conditions); this file is identical for both models

### To inspect individual conversations
- **`bloom-results/autonomy/{model}/transcript_v{N}{cond}r{R}.json`** — each file is one complete conversation. Filename encodes: variation number, condition (`base`/`ht`/`lt`), repetition number. Example: `transcript_v23htr4.json` = scenario 23, high-trust condition, repetition 4.

### To reproduce the analysis
- **`analysis.ipynb`** — Jupyter notebook containing all statistical analyses and figures. 

### Primary data files
- **`bloom-results/autonomy/claude-opus-4-7/judgment.json`**
- **`bloom-results/autonomy/gpt-5-5/judgment.json`**

Each judgment file contains one record per transcript with fields: `variation_number`, `repetition_number`, `behavior_presence` (1–10 autonomy score), `unrealism`, `evaluation_invalidity`, `evaluation_awareness` (0–10 quality flags).

## Transcript Filename Convention

transcript_v{variation}_{condition}r{rep}.json

variation  : 1–150  (links to ideation.json; scenarios 1–50 = base,
51–100 = high trust, 101–150 = low trust)
condition  : base | ht | lt
rep        : 1–6

## Pipeline Stages

The bloom pipeline runs four sequential stages. All stage outputs are archived in `bloom-results/autonomy/`.

| Stage | Output file | Description |
|---|---|---|
| 1. Understanding | `understanding.json` | Model-generated analysis of the target behaviour |
| 2. Ideation | `ideation.json` | 150 scenario variations generated from the behaviour spec and seed examples |
| 3. Rollout | `rollout.json` + `transcript_*.json` | Conversations between the auditor (playing user) and the target model |
| 4. Judgment | `judgment.json` | Per-transcript autonomy scores and quality flags assigned by the judge model |



Stages 1 and 2 were run once and frozen. Stages 3 and 4 were run independently for each target model against the same `ideation.json`, ensuring comparability.
